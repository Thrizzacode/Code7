1. 簡介

Code7 是一款專為簡化 SVN 合併流程設計的桌面工具。它能自動識別專案路徑，協助開發者快速在 branches、qat 與 stg 三大環境之間進行代碼合併、衝突處理與工作目錄同步。

✨ v1.13.x 新功能：合併預覽（執行合併前先以 svn merge --dry-run 列出預期異動與衝突，確認後才動工，可於設定關閉）、合併失敗或中止時一鍵「放棄合併並還原」尚未提交的變更。v1.12.x：發布站點頁面（App 內直接觸發並追蹤 Jenkins pipeline，動態產生參數表單、每 3 秒輪詢建置狀態與 Console Log）。v1.11.x：Revision 顯示篩選器（全部 / 未合併 / 已合併三段式切換）。v1.10.x：鏈式合併（branches→QAT→STG 一次搞定，實驗性功能）。v1.9.x：AI 自動生成 Commit Message（支援 Groq / Gemini）、合併成功後自動帶入 Merged revision 訊息、合併與提交前版本落後警告，以及 Revision Picker 彈性全選模式。

2. 快速入門：首次執行

若您是第一次開啟 Code7，系統會引導您進行初始設定：

  1. 點擊 「匯入工作目錄」 按鈕。
  2. 選擇存放所有 Fz 專案的 父資料夾（例如：D:\Workspace\Fz_Projects）。
  3. App 會自動掃描該目錄下所有符合規則的 SVN Working Copy 並匯入專案清單。

3. 核心功能：合併版本 (Merge)

第一步：選擇專案

在頂部導覽列選擇您要作業的專案。選擇後，App 會自動抓取該專案對應的「本地」與「遠端」版本資訊。

第二步：設定來源與目標

  • 來源 (Source)：選擇來源環境（如 branches）及其版本號。
  • 目標 (Target)：選擇目標環境（如 qat）及其對應版本。
  • ✨ 智能同步 (Smart Sync)：如果您選擇的版本在本地尚未下載（Working Copy 不存在），路徑下方會出現 「同步至本地」 按鈕。點擊後系統會自動執行 svn update 並展開目錄（Infinity Depth）。

第三步：執行合併

  1. 選取 Revisions：勾選您想要合併的版本紀錄。
    • 顯示篩選：工具列新增「全部 / 未合併 / 已合併」三段式按鈕，可快速過濾顯示的 revision；與下方文字搜尋框疊加使用效果更佳。
    • 進階過濾：搜尋框支援 正規表達式 (RegExp)。
    • 重複合併 (Cherry-pick)：即使已合併，仍可手動勾選重新合併。
  2. 點擊下方的 「執行合併 (Merge)」。系統會先檢查本地版本是否落後伺服器 HEAD，若落後會要求確認再繼續。
  3. ✨ 合併預覽 (v1.13.0)：預設會在真正合併前先跑 svn merge --dry-run，以對話框列出預期的更新／新增／刪除／衝突檔案清單，確認後才實際套用；可於 設定 > 外部合併工具 >「合併前顯示預覽」 關閉。鏈式合併每一站都會套用。
  4. 🔗 鏈式合併（實驗性）：當來源為 branches、目標為 qat 時，勾選「🔗 鏈式合併」並選擇 STG 版本，系統會在 branches→QAT 合併完成後，自動接續執行 QAT→STG 合併，一次流程完成雙段合併。
  5. 後續流程判斷：
    • 無衝突 (Success)：提示成功，並自動從 SVN Log 組合 Merged revision(s) ... from ... 格式的 Commit Message 帶入提交欄位，可直接點擊「提交 (Commit)」完成。
    • 有衝突 (Conflict)：彈出衝突清單，點擊「使用外部工具解決」開啟 TortoiseMerge（會自動帶入 base／theirs／mine 三方檔案）。若中途不想解了，可點擊 「放棄合併並還原」 ，系統會對尚未提交的工作目錄執行 svn revert -R 並清除本次合併新增的檔案，回到合併前狀態（v1.13.0）。

4. 獨立提交功能 (Commit)

如果您需要單獨處理某個環境的檔案提交（非合併流程），請切換至  「提交 (Commit)」  分頁：

  1. 掃描變更：選擇環境與版本後，App 會自動顯示工作區所有變更檔案（修改、新增、刪除、衝突）。
  2. 檔案預覽：「快點兩下」  檔案或是點擊右側圖示，可直接開啟  TortoiseDiff  比對差異，或是直接開啟該檔案。
  3. ✨ AI 生成訊息：勾選要提交的檔案後，點擊「✨ AI 生成」按鈕，系統會自動對選取的檔案執行 SVN diff 並呼叫 AI 生成符合 Conventional Commits 規範的提交訊息（需先在設定中配置 API Key）。
  4. 執行提交：輸入或確認 Commit Message 後，系統會先檢查本地版本是否落後伺服器 HEAD，若落後會要求確認再提交。

5. 進階功能：同步更新 (SVN Update)

  • 蠟筆取新：點擊頂部欄 同步更新 > 蠟筆取新。
  • 批次更新所有專案：點擊 同步更新 > 蠟筆取新所有子專案。右上角會顯示實體進度條。

6. 個人化設定與更新 (Settings)

點擊右上角的 ⚙️ 設定 圖示進入：

  • ✨ IIS 版本切換器：
    • 一鍵整機切換：支援自動同步 hosts 檔案與 applicationHost.config 至各分支版本。
    • 團隊共享配置 (v1.6.1)：新增  「恢復預設」  按鈕，點擊後可一鍵恢復為團隊專屬網路路徑 (\\192.168.70.17...)，支援自動識別最新版本。
    • 排序優化 (v1.6.1)：版本清單現在會依據編號  倒序排列 (最新版本置頂)，方便快速選取。
    • 偵測功能：系統會自動偵測目前 IIS 正在運行的分支版本。
    • 安全性：套用時會彈出 Windows UAC 授權（黑畫面確認），請點選「是」才能寫入系統路徑。
  • ✨ AI 訊息生成：
    • AI 提供者選擇：支援 Groq（預設）與 Google Gemini 兩種提供者。
    • API Key 管理：分別輸入各提供者的 API Key；切換時互斥顯示對應欄位。
    • 自訂提示詞：可修改 AI 提示詞模板，並提供「恢復預設提示詞」按鈕還原為 Conventional Commits 規範格式。
  • 佈景主題切換：提供 PHYSICAM (紅)、TECHNOLOM (藍) 等 5 種風格色彩，並支援  深淺色模式。
  • 專案/工具管理：可手動排除批次同步專案，或指定特定的 TortoiseMerge 路徑。此區塊另提供 「合併前顯示預覽」 開關（v1.13.0，預設開啟）。
  • ✨ Jenkins 發布 (v1.12.0)：設定 Jenkins Base URL、使用者名稱、API Token（於 Jenkins 個人設定產生）與 View 名稱（預設「方舟_Main_主任務」），供「發布」頁面連線使用。
  • App 更新管理：查看目前的 App 版本並手動檢查更新。

7. 發布站點 (Publish)

在頂部導覽列點擊 發布 (Publish)，即可直接在 App 內操作 Jenkins pipeline，不必開啟 Jenkins 網頁。需先於 設定 > Jenkins 發布 填妥連線資訊。

  • 作業清單：左側自動列出設定 View 底下的所有 job（資料夾會自動過濾），並顯示上次建置的狀態色點。job 有增刪時點擊 🔄 重新整理即可同步。
  • 動態參數表單：選定 job 後，依其參數定義自動產生對應欄位——下拉選單 (Choice)、核取方塊 (Boolean)、單行輸入 (String)、多行文字 (Text)，並原樣顯示每個參數的說明文字；分隔線參數 (ParameterSeparatorDefinition) 會呈現為區段標題。無參數的 job 則直接觸發建置。
  • 觸發與追蹤：點擊右上角 觸發建置 後，頁面每 3 秒輪詢一次狀態，依序顯示 排隊中 → 建置中 #N → 成功／失敗 與耗時。
  • Console Log：觸發後自動展開，固定於面板底部、可獨立捲動並拖曳調整高度，新輸出會即時附加。切離發布頁時輪詢會自動停止。
  • 連線注意：僅支援 basic auth（使用者 + API Token）；API Token 以明碼儲存於本機設定檔，與 AI API Key 相同。

8. 常見問題 (FAQ)

  • Q: 為什麼顯示「載入失敗」？
    • A: 請確保已安裝 SVN CLI 工具並加入環境變數。
  • Q: IIS 切換時為什麼沒反應？
    • A: 請確保您在 UAC 提示時有點擊「是」。若權限不足，系統檔案將無法被覆蓋。

9. 版本記錄 (Changelog)

v1.13.0 (2026-09-04)

  • 【新增】合併預覽 (Merge Preview)：單段與鏈式合併每一站在真正執行前，先跑 svn merge --dry-run，以對話框列出預期的更新／新增／刪除／衝突檔案清單與數量，確認後才動工。可於 設定 > 外部合併工具 >「合併前顯示預覽」 開關關閉（預設開啟）。
  • 【新增】合併失敗／中止自動回退：merge 指令失敗、或衝突未解完就中止時，對話框提供「放棄合併並還原」，對尚未提交的目標工作目錄執行 svn revert -R 並清除本次合併新增且仍未追蹤的檔案。鏈式合併僅還原當前未提交站，已提交站不受影響。
  • 【修正】TortoiseMerge 解衝突未帶入三方路徑：svn info --xml 的 <conflict> 節點位置判斷錯誤，導致開啟 TortoiseMerge 時只有 base 欄位有值。現已正確帶入 base／theirs／mine。
  • 【修正】衝突對話框關閉後背景輪詢未停止：關閉衝突對話框（含「放棄合併並還原」）後，狀態輪詢會一併停止，不再因 revert 清掉衝突標記而誤判為「已解決」重開對話框。
