## 2. 主程序 Jenkins 服務（`src/main/jenkins-service.js`）

- [x] 2.1 建立 `jenkins-service.js` 骨架，實作依「決策二：認證採 basic auth（使用者加 API Token），寫入 Authorization header」的共用請求函式，以及依「決策八：統一錯誤形狀與錯誤碼常數」的錯誤碼常數（`CONFIG_MISSING`、`AUTH_FAILED`、`NOT_FOUND`、`NETWORK_ERROR`、`CRUMB_FAILED`），並依「決策一：Jenkins 溝通集中於主程序 jenkins-service.js，使用 Node 內建 fetch」僅用內建 `fetch`。滿足 Requirement: Uniform Jenkins error reporting。行為：未設定 Base URL／使用者／Token 時回傳 `{ success:false, error:'CONFIG_MISSING' }`；HTTP 401／403 回傳 `AUTH_FAILED`；連線失敗／逾時回傳 `NETWORK_ERROR`。驗證：Node 手動呼叫，分別以空設定、錯誤 token、錯誤 host 觀察回傳的 error 碼。
- [x] 2.2 實作 `listJobs()`，依「決策四：Job 清單來源為 view API，每次進入頁面重新抓取」呼叫 `GET /view/<jenkinsViewName>/api/json?tree=jobs[name,url,color]`，job 與 view 名稱以 `encodeURIComponent` 編碼。滿足 Requirement: List all jobs in the configured view。行為：回傳 `{ success, jobs:[{name,url,color}] }`；view 不存在（HTTP 404）回傳 `{ success:false, error:'NOT_FOUND' }`。驗證：對真實 Jenkins view 呼叫，比對回傳 job 數與 Jenkins 網頁一致；再以不存在的 view 名稱確認 `NOT_FOUND`。
- [x] 2.3 實作 `getJobParameters(jobName)`，呼叫 `GET /job/<job>/api/json?tree=property[parameterDefinitions[name,type,description,defaultParameterValue[value],choices]]`。滿足 Requirement: Render a dynamic form from job parameter definitions（資料面）。行為：回傳 `{ success, hasParams, params:[{name,type,description,defaultValue,choices}] }`；無 `parameterDefinitions` 時 `hasParams:false`、`params:[]`。驗證：對「發布方舟」呼叫，確認回傳 Version 的 `choices`、TargetCompanyIds 的 `defaultValue`、各 Deploy 開頭參數的 type 為 `BooleanParameterDefinition`。
- [x] 2.4 實作 `triggerBuild(jobName, params)`，依「決策三：以 crumb 通過 CSRF 保護，僅 POST 請求需要」先 `GET /crumbIssuer/api/json` 再 `POST /job/<job>/buildWithParameters`（無參數 job 改打 `/job/<job>/build`），從回應 `Location` header 取 queue item URL。滿足 Requirement: Trigger a parameterized build。行為：回傳 `{ success, queueUrl }`；crumb 請求失敗時不帶 crumb 重試 POST 一次，仍失敗才回 `CRUMB_FAILED`；401／403 回 `AUTH_FAILED` 且不觸發。驗證：對測試 job 觸發，確認 Jenkins 出現排隊項目且回傳的 `queueUrl` 可再查詢；以錯誤 token 確認回 `AUTH_FAILED`。
- [x] 2.5 實作 `getQueueStatus(queueUrl)` 與 `getBuildStatus(jobName, buildNumber)`，支撐「決策六：建置狀態輪詢分三階段，由渲染層以固定間隔驅動」。滿足 Requirement: Poll build progress to completion（資料面）。行為：`getQueueStatus` 回傳 `{ success, state:'queued'|'running'|'cancelled', buildNumber? }`（`executable.number` 出現時帶 `buildNumber`）；`getBuildStatus` 回傳 `{ success, building, result, durationMs, timestamp }`。驗證：觸發一次建置後輪詢，確認 state 由 `queued` 轉為帶 `buildNumber`，再確認 `building` 由 true 轉 false 且 `result` 與 Jenkins 建置歷史一致。
- [x] 2.6 實作 `getConsole(jobName, buildNumber, start)`，呼叫 `GET /job/<job>/<n>/logText/progressiveText?start=<offset>`，以回應 `X-Text-Size` 作 `nextStart`、`X-More-Data` 判斷 `hasMore`。滿足 Requirement: Show progressive console log。行為：回傳 `{ success, text, nextStart, hasMore }`。驗證：對已完成建置從 `start=0` 連續呼叫，確認拼接後的文字與 Jenkins Console Output 相同且 `hasMore` 最終為 false。
